# Linux 网络流量监控系统 —— 产品设计文档

> 版本：v0.3（V0.1 MVP + V0.3 远程客户端）  
> 日期：2026-09-02（V0.3 更新：2026-09-05）  
> 状态：方向已确认，进入开发规划

## 1. 产品定位

一款运行在 **Linux 上的轻量网络流量监控工具**：实时看清"流量从哪来、到哪去、有多少"，并且对自身抓包丢包保持诚实可见。

**目标场景**

- 运维 / 开发人员查看服务器实时带宽与会话构成；
- 网关 / 路由器管理员掌握网络流量分布（后续版本扩展）；
- 学习网络协议与流量分析的实验平台。

**产品形态**：原生 Linux 守护进程（Go 语言），自带 HTTP API 与网页仪表盘，本地存储，浏览器访问即用；不依赖任何外部服务。

## 2. MVP 核心目标

跑通一条完整的"看见流量"闭环：

```text
网卡抓包 → 协议解析 → 会话聚合 → 指标统计 → 本地存储 → 网页展示
```

只做让用户"看得见、查得到、信得过"的最小功能集，其余全部后置。

## 3. MVP 主要功能

| 功能模块 | 具体内容 |
| --- | --- |
| 实时监控 | 当前带宽（bps）、包速率（pps）、并发连接数，1 秒刷新 |
| 会话明细 | 5 元组会话：源/目的 IP、端口、协议、包数、字节数、起止时间；双向归并、分页查询、按时间/IP 过滤 |
| 历史曲线 | 近 1 小时带宽曲线（1 秒粒度），服务重启后数据不丢 |
| 自身健康 | 收包数、丢包数、流表大小可见；发生抓包丢包时页面明确提示 |
| 数据存储 | SQLite 本地持久化，指标与流记录分表，启动时按保留策略清理 |
| 系统配置 | TOML 配置：监控网卡、BPF 过滤表达式、采样间隔、存储路径、保留天数 |
| 网页仪表盘 | 带宽曲线 + 会话表格 + 丢包状态；轮询 API（MVP 不做 WebSocket） |

**配套能力**：pcap 文件回放模式，所有功能可脱离真实网络运行与自动化测试。

## 5. 使用流程

1. 在 Linux 上编译 `netmon` 单二进制；
2. 编辑 `config.toml`（选择监控网卡）；
3. systemd 托管，开机自启（root / `CAP_NET_RAW`）；
4. 浏览器访问 `http://<这台Linux的IP>:8080` 查看仪表盘；
5. 数据全部保存在本机，页面只负责展示。

## 6. MVP 完成定义（验收标准）

- [ ] 网页实时带宽 / 并发连接数在 1 秒内刷新；
- [ ] 过去 1 小时历史曲线可查询，服务重启后不丢；
- [ ] 会话列表可翻页、可按 IP/时间过滤；
- [ ] 人为制造抓包丢包时，页面出现明确提示；
- [ ] pcap 回放模式下全部功能可离线运行；
- [ ] 每个模块有单元测试，关键链路有回放集成测试，全部通过。

## 8. V1 远程桌面客户端（V0.3，已实现）

**定位**：个人练手 + 单机自用。在保持"Linux 端网页即用"不变的前提下，新增 Windows 桌面客户端作为远程查看形态：

- **技术形态**：Tauri 2 + Vue 3 + Vite + ECharts（目录 `client/`），Electron 未采用（体积大）；
- **远程连接**：Windows 客户端填 Linux 的 IP:端口（默认 8080）与访问令牌；数据请求统一经 Rust 命令层（reqwest）发起，令牌保存在进程状态，规避 CORS；
- **功能**：连接管理（本地持久化）、实时 KPI（1s 轮询）、最近 1 小时历史曲线、会话明细（IP/协议过滤 + 分页）、系统健康；
- **配套后端**：Linux 端新增可选 Bearer Token 鉴权（`[api] token`，默认关闭）；
- **范围说明**：练手为主，控制类功能（限速）暂不纳入本版本；实时推送（WebSocket）在 V2/V3 引入。

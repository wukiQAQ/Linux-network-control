## 2. SQLite 接入设计

### 2.1 为什么用纯 Go 驱动

SQLite 常见驱动 `mattn/go-sqlite3` 依赖 CGO，跨平台（Windows↔Linux）编译需要两套 C 工具链。V0.2 选用 **`modernc.org/sqlite`**：它是 SQLite 的纯 Go 移植，无需 CGO，同一份源码可直接交叉编译出 Windows 与 Linux 二进制，与本项目的"单二进制部署"目标一致。

### 2.2 接入方式（接口不变）

V0.1 已经预留了 `storage.Backend` 接口，V0.2 只是新增一个实现：

```text
storage.Backend（接口）
   ├── FileStore      （V0.1：JSONL，保留，可配置切换）
   └── SQLiteStore    （V0.2：默认后端）
```

上层（`app`、`api`）只依赖接口，因此接入 SQLite **没有改动任何业务代码**，仅新增：

- `internal/storage/sqlite.go`：SQLite 实现；
- `internal/config`：新增 `storage`（sqlite/file）与 `sqlite_path` 配置；
- `cmd/netmon/main.go`：按配置选择后端（默认 sqlite）。

### 2.3 表结构与关键实践

```sql
CREATE TABLE metrics (ts INTEGER, series TEXT, tags TEXT, value REAL);
CREATE INDEX idx_metrics_series_ts ON metrics(series, ts);

CREATE TABLE flows (start INTEGER, end INTEGER, src_ip TEXT, src_port INTEGER,
                    dst_ip TEXT, dst_port INTEGER, proto INTEGER, packets INTEGER,
                    bytes INTEGER, tcp_flags INTEGER, iface TEXT, machine_id TEXT);
CREATE INDEX idx_flows_start ON flows(start);
```

工程细节：

- `PRAGMA journal_mode=WAL`：写读并发下性能更好；
- `PRAGMA busy_timeout=5000`：避免并发写入时立刻报锁；
- `db.SetMaxOpenConns(1)`：SQLite 是单写者模型，串行化写入最稳；
- 时间一律存 **UnixNano**（INTEGER），与接口层 `time.Time` 互转，精度无损；
- `Prune()` 按保留策略删除过期行，与 FileStore 语义一致；
- 首次打开自动 `MkdirAll` 数据库目录，无需手动建目录。

### 2.4 验证

## 3. 与 Linux 虚拟机（WSL Ubuntu）的连接原理

### 3.1 部署形态

```text
Windows（本机，开发/浏览）
   │ 浏览器访问 http://localhost:8080
   │（WSL2 NAT 自动把 Windows localhost 转发到 Linux）
   ▼
WSL Ubuntu（Linux "虚拟机"，运行 netmon）
   ├── netmon（Linux amd64 二进制，synthetic 数据源）
   ├── netmon.db（SQLite，WAL）
   └── 端口 :8080 监听
```

### 3.2 运行原理

1. **编译**：在 Windows 上用 `GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build` 产出 Linux 二进制（纯 Go 无 CGO，因此可以跨平台编译）；
2. **传输与启动**：把二进制复制进 WSL（本验证放在 `~/`），`chmod +x` 后用 `nohup ... &` 后台运行；netmon 内部是单进程：合成数据源按 pps 产包 → 解析 → 流表 → 聚合 → 每 1s 写 SQLite，同时 HTTP 服务监听 `:8080`；
3. **网络连通**：WSL2 默认 NAT 模式，Windows 侧访问 `localhost:8080` 会被 WSL 的端口转发规则转发到 Ubuntu 内的 `:8080`（与访问一台远程 Linux 服务器同理，只是少了公网 IP 这一步）；
4. **验证结果**：Windows 端请求 `/api/v1/traffic/now` 返回 `recv=1314, bps≈902k, conns=1143`，仪表盘页面返回 HTTP 200；随后 `pkill` 停止进程，验证完毕。

> 换成真实服务器时，把第 2 步的"复制进 WSL"改为 `scp`/部署工具，把第 3 步的 `localhost` 换成服务器 IP 即可——**程序本身零改动**。

## 4. 整体运行原理（V0.2 版）

```text
┌──────────────────────── netmon 单进程（Go） ────────────────────────┐
│                                                                    │
│  capture（数据源）                                                  │
│    synthetic（演示） / pcap 回放（测试） / live AF_PACKET（Linux 抓包）│
│        │ 原始帧                                                   │
│        ▼                                                          │
│  parser（解析） → 剥离 以太网/IPv4/TCP|UDP，产出 5 元组               │
│        ▼                                                          │
│  flow（流表） → 双向归并、计数；30s 空闲 + 5min 硬超时过期             │
│        ▼                                                          │
│  aggregator（聚合）→ 1s tick 输出 bps/pps/conns/丢包采样             │
│        │                                                          │
│        ├──→ storage（SQLite）  指标/会话持久化 + 保留策略清理          │
│        └──→ api（REST /api/v1 + go:embed 仪表盘）                   │
│                  ▲                                                │
└──────────────────┼────────────────────────────────────────────────┘
                   │ 浏览器 1s 轮询
                   ▼
              仪表盘页面（本机或远程浏览器）
```

关键不变式：

1. **数据只在 Linux 侧流动**——抓包、解析、聚合、存储全部发生在 netmon 进程内，浏览器只是"显示器"；
2. **存储可替换**——SQLite 与 FileStore 都实现同一个 `Backend` 接口，切换只改配置；
3. **单位不换算**——后端存原始数值（字节/包/时间戳），单位切换属于前端；
4. **自身可观测**——解析失败即 `RecordDrop`，丢包数、收包数通过 `/health` 与页面暴露。

## 5. 运行与验证命令

```bash
# 1) 本机（Windows）验证，默认 SQLite
go run ./cmd/netmon                 # 访问 http://localhost:8080

# 2) 交叉编译并部署到 Linux（虚拟机/服务器）
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -o netmon-linux ./cmd/netmon
scp netmon-linux user@server:~/ && ssh user@server './netmon-linux'
# 浏览器访问 http://server-ip:8080

# 3) 切回 JSONL 文件后端（如需）
# 配置文件中设置 storage = "file"
```

## 7. CentOS 真实环境部署记录（2026-09-04 验收）

- **环境**：CentOS（VMware 虚拟机，IP 192.168.161.128），用户 `wuki`，通过 FinalShell（SSH/SFTP）远程管理；
- **流程**：Windows 交叉编译 → FinalShell 拖拽上传 `/home/wuki/netmon-linux` → 编写 `/home/wuki/config.toml`（`source="live"`、`iface="ens33"`）→ `sudo ./netmon-linux -config config.toml` → `firewall-cmd` 放行 8080 → Windows 浏览器访问 `http://192.168.161.128:8080`；
- **验收数据**：`recv_packets` 7170 → 9792 持续增长；`bps` ≈ 82K~175K；`pps` ≈ 52~131；`conns=3`；仪表盘页面 HTTP 200；
- **说明**：`drop_packets` 计数中包含 ARP 等非 IPv4 帧（MVP 只解析 IPv4，属解析范围限制，非真实丢包）；配置项与 systemd 常驻方式详见《使用指南》。

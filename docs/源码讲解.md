# Linux 网络流量监控系统（MVP）源码讲解

> 版本：v0.1  
> 日期：2026-09-03  
> 范围：本文档讲解 MVP 全部 Go 源码的模块划分、实现原理与测试方式。
> 阅读建议：对照 [技术方案](技术方案.md) 第 3 章看目录结构，再按本文第 2 节的数据流逐模块阅读。

## 1. 目录结构总览

```text
cmd/netmon/                # 程序入口：装配与启动
internal/config/           # 配置加载（TOML 轻量子集）
internal/capture/          # 采集层：接口 + 三种数据源
internal/parser/           # 协议解析：以太网 / IPv4 / TCP / UDP / ICMP
internal/flow/             # 会话表：5 元组聚合、双向归并、双超时过期
internal/aggregator/       # 聚合器：秒级 bps / pps / 连接数指标
internal/storage/          # 存储接口 + JSONL 文件实现
internal/api/              # REST API（/api/v1/...）
internal/webui/            # 内嵌仪表盘页面（go:embed）
internal/app/              # 应用装配与主循环（管道调度）
netmon.example.toml        # 配置示例
docs/产品设计文档.md         # 产品设计（需求来源）
docs/技术方案.md            # 技术方案（架构来源）
```

依赖方向是单向的：`capture → parser → flow → storage`，`app` 负责把它们串起来，`api` 只读聚合器/存储/流表。任何一层都不反向依赖上层，这是"采集方式、存储后端可替换"的结构保证。

## 2. 核心数据流（一个包的一生）

```text
数据源(Source)              原始帧 []byte
   │  Next(ctx)
   ▼
app.HandlePacket
   ├─ parser.Parse → Info{5 元组 + TCP 标志}
   ├─ 解析失败 → aggregator.RecordDrop()      ← "丢包诚实可见"
   ├─ 成功 → flow.Table.Handle(...)           ← 双向归并进会话表
   └─ aggregator.Observe(帧长)                ← 累计字节/包

每个 tick（默认 1s）：
   aggregator.Tick → Sample{bps,pps,conns,...}
   flow.Table.Expire  → 过期的会话 → storage.AppendFlow
   aggregator 采样 → storage.AppendMetric（5 个指标序列）
   storage.Prune（按保留策略清理）

浏览器 1s 轮询 → /api/v1/traffic/now、/history、/sessions、/health
```

## 3. 模块逐个讲解

### 3.1 config —— 配置即"装配清单"

**职责**：把 TOML 配置变成各模块的构造参数。

**实现原理**：实现了一个极简 TOML 子集解析器——按 `[section]` 分组，`key = value` 存入扁平 map，再由 `apply()` 逐个写入 `Config` 结构体。未配置的项走 `Default()`，未知项忽略。

**为什么这样做**：MVP 不需要完整 TOML 语法；保留 `[section]` 结构是为了将来新增配置项时不用改解析器。

**测试**：`config_test.go` 覆盖正常解析、`source=replay` 缺少 `replay_file` 的校验、文件不存在的错误。

### 3.2 capture —— 把"抓包方式"藏进接口里

**职责**：产出原始报文 `Packet{Ts, Raw, Iface}`，屏蔽三种数据源的差异。

**实现原理**：

```go
type Source interface {
    Next(ctx context.Context) (*Packet, error)
    Close() error
    Stats() Stats
}
```

- **Synthetic**：`time.NewTimer(1s/pps)` 节流，随机构造内网→公网的 TCP/UDP 帧。用途：开发、演示、集成测试，不需要 root。
- **PcapFile**：自己解析 pcap 经典格式——24 字节全局头（含 magic 判断大小端/纳秒）+ 16 字节记录头。用途：离线回放，也是全部自动化测试的数据源。
- **Live（Linux）**：`AF_PACKET + SOCK_RAW` 原始套接字绑定网卡索引后 `Recvfrom` 逐帧读取，属于"最贴近网卡"的实现；需要 root / `CAP_NET_RAW`。文件带 `//go:build linux`，非 Linux 平台编译时自动替换为返回错误的桩。

**为什么这样设计**：上层永远不感知"数据是从网卡、文件还是程序里来的"。换数据源 = 改一行配置。

**测试**：`capture_test.go` 验证 pcap 写入→读取逐字节一致、EOF、统计计数、Synthetic 的上下文取消。

### 3.3 parser —— 只剥头，不算校验和

**职责**：从以太网帧中提取 `Info{协议、源/目的 IP、端口、TCP 标志、负载长度}`。

**实现原理**：

```go
off := 12                    // EtherType 字段位置
etype := ...                 // 循环跳过 VLAN/QinQ 标签
l3 := off + 2                // IP 层起点（关键：+2 才是负载）
verIHL := b[l3]              // 版本=高 4 位，IHL=低 4 位×4
l4 := l3 + ihl               // 传输层起点
```

解析遵循一个原则：**只剥头部、提取元数据，不做校验和验证**——内核已经校验过到达的数据包，业务层重复计算只会浪费 CPU。TCP 头部的数据偏移字段用来计算含选项的头部长度，保证负载长度正确。

**测试**：TCP/UDP/ICMP 三种协议、SYN 标志、VLAN 跳过、短报文与未知 EtherType 的错误路径。

### 3.4 flow —— 双向报文如何变成"一条会话"

**职责**：5 元组聚合 + 双向归并 + 过期。

**实现原理**：这是全系统最核心的数据结构，三个要点：

1. **双向归并**：`Key.Canonical()` 把 5 元组按"源地址、源端口、协议、目的地址、目的端口"字典序排序。A→B 和 B→A 排序后得到同一个 Key，天然归并为一条流，而 `Flow.SrcIP` 保留**首次观测方向**用于展示。
2. **增量更新**：`Handle()` 命中已有流只做 `End/计数/标志` 更新，不新建对象，避免哈希表频繁分配。
3. **双超时过期**：空闲超时（默认 30s，适合 UDP 这种无状态协议）+ 硬超时（默认 5min，防止 TCP 长连接永不释放）。`Expire(now)` 每次 tick 清扫，返回快照交给存储层。

**测试**：双向 3 个包归并为 1 条流且字节数相加正确；空闲超时只淘汰"冷"流；持续有流量时硬超时仍生效。

### 3.5 aggregator —— 增量累加，定时快照

**职责**：把逐包事件压缩成 1s 指标：bps、pps、并发连接、新建连接、丢包事件。

**实现原理**：

```go
type Agg struct {
    bytes, pkts uint64   // 周期内累计（tick 后清零）
    total       uint64   // 历史累计（健康页收包总数）
    drops       uint64   // 历史累计丢包
    ring        []Sample // 环形历史，默认 3600 个采样点
}
```

`Observe()` 只做加法；`Tick()` 输出一个采样点后清零周期计数，用 `总字节×8 / 周期秒数` 计算 bps。首帧建立基线，启动期间的计数按 1s 折算，不丢失。环形缓冲保证 API 能拿到近 1 小时数据，同时内存有上界。

**测试**：构造 3000 字节/2 包/1 丢包后 tick，断言 bps=24000、pps=2；环形缓冲超过容量后自动截断。

### 3.6 storage —— 接口可替换，落盘可重启

**职责**：持久化指标与会话，提供查询。

**实现原理**：定义 `Backend` 接口（追加/查询/清理/关闭），MVP 提供 `FileStore` 实现：**内存索引 + JSONL 追加写 + 启动时全量加载 + 保留策略重写**。每个指标/会话一行 JSON，追加写天然适合顺序 IO；`Prune()` 按保留时长清掉过期数据并重写文件。

> 与《技术方案》的差异说明：方案原定 SQLite，但本仓库当前处于无法拉取第三方依赖的离线环境，故先交付语义等价的 FileStore。上层代码只依赖 `Backend` 接口，接入 SQLite 只需新增一个实现（`OpenSQLite(dir)`），`app` 与 `api` 无需改动。

**测试**：指标增删查、会话按 IP/协议/端口过滤与分页、倒序返回；关闭后重开验证持久化；Prune 只保留窗口内数据。

### 3.7 api —— 版本化 REST，页面随二进制发布

**职责**：把内存中的实时数据与存储中的历史数据暴露为 JSON。

**实现原理**：

```text
GET /api/v1/traffic/now      → 聚合器最近采样 + 健康统计
GET /api/v1/traffic/history  → 多个指标序列对齐到同一时间轴
GET /api/v1/sessions         → 存储层过滤 + 分页
GET /api/v1/health           → 收包/丢包/丢包率/流表大小
GET /                        → go:embed 的仪表盘页面
```

history 的关键是把 5 个指标序列（bps/pps/conns/newconns/drops）按 `since/step` 参数切成同一组时间桶再求平均，前端拿到一份对齐后的 `points` 数组即可画图。页面通过 `go:embed` 打进二进制，保持"单文件部署"。

**测试**：`httptest` 起真实服务，验证 now/health 字段、history 桶数、会话过滤、静态页标题。

### 3.8 app —— 调度者（可单测的主循环）

**职责**：把各模块串成管道并驱动运行。

**实现原理**：把主循环拆成两个可单测方法 + 一个无限循环：

- `HandlePacket(p)`：解析 → 流表 → 聚合，解析失败计丢包；
- `TickOnce(now)`：聚合采样 → 过期会话落盘 → 指标落盘 → 保留策略清理；
- `Run(ctx)`：采集 goroutine 把报文塞进有界 channel，主循环在 `包/时钟/取消` 三个事件间 select；数据源结束（如回放 EOF）会先排空缓冲再退出。

**测试**：`app_test.go` 是**关键链路回放集成测试**——构造 4 个报文（含一对双向 TCP + 一个 UDP）写成 pcap，回放后断言：双向会话合并为 1 条（包数=3）、共 2 条会话、指标点写入、首次观测方向保留。

## 4. 如何运行

```bash
# 开发/演示（Windows、无网卡环境都可以）：合成流量
go run ./cmd/netmon
# 打开 http://localhost:8080

# 回放 pcap（离线、自动化测试友好）
# 编辑 netmon.example.toml：source="replay", replay_file="sample.pcap"
go run ./cmd/netmon -config netmon.example.toml

# Linux 真实抓包
# source="live", iface="eth0"，需要 root 或 CAP_NET_RAW
```

## 5. 验收标准对照

| 产品设计验收项 | 落点 |
| --- | --- |
| 实时指标 1s 刷新 | 前端 `setInterval 1s` 轮询 `/now`；聚合器 tick=1s |
| 历史曲线重启不丢 | tick 指标写入 FileStore，启动全量加载 |
| 会话翻页/按 IP 过滤 | `/sessions?ip=&proto=&port=&page=` |
| 丢包页面提示 | 解析失败 `RecordDrop` → `/now.drop_packets` → 页面横幅 |
| pcap 回放全功能 | `capture.PcapFile` + `app_test` 回放集成测试 |
| 单测/集成测试全绿 | `go test ./...` 8 个包全部通过 |

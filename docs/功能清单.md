并且对自身抓包丢包保持诚实可见。

## 1. 三种使用形态

| 形态 | 启动方式 | 适用场景 |
| --- | --- | --- |
| **Linux 采集端** `netmon` | `sudo ./netmon-linux -config config.toml`（systemd 托管可开机自启） | 生产：真实抓包、存储、告警、运维动作 |
| **内嵌网页仪表盘** | 采集端自带，浏览器访问 `http://<Linux-IP>:8080` | 零安装查看；不带鉴权的静态页 + 受鉴权的 `/api/` |
| **Windows 客户端 MeTD** | `metd.exe`（Tauri 2 + Vue 3） | 日常使用：多机管理、图表、运维指令、插件面板 |

离线能力：`replay`（回放 pcap）与 `synthetic`（进程内造包）两种数据源，让全部功能脱离真实网络即可运行与回归测试。

## 2. 采集端功能（按数据流）

### 2.1 数据源

| 数据源 | 说明 | 版本 |
| --- | --- | --- |
| `live` | Linux AF_PACKET 直读网卡，需 root / `CAP_NET_RAW` | V0.1 起 |
| `replay` | 顺序回放 pcap（以太网链路类型），文件读完即退出 | V0.1 起 |
| `synthetic` | 进程内构造 IPv4/TCP/UDP 报文，按 `pps` 限速 | V0.1 起 |

### 2.2 采集层

| 功能 | 说明 | 版本 |
| --- | --- | --- |
| AF_PACKET 抓包 | `socket(AF_PACKET, SOCK_RAW)` + 绑定网卡，收全部以太类型 | V0.1 |
| 多队列并行收包 | `[capture] readers = 1~8`，多套接字加入同一 `PACKET_FANOUT`（按**流哈希**分流，同一会话顺序不乱）；任一步失败自动回退单队列 | V0.17.0 |
| 多队列 CPU 绑定 | `[capture] cpu_pin = true`：各读循环固定 OS 线程并绑到不同 CPU（按 cgroup/taskset 允许集合分配，核不够循环复用；读不到列表或绑定失败只记日志并继续）；能力上报 `capture.cpupin` | V0.21.0 |
| 用户态开销优化 | 读缓冲 `sync.Pool` 复用、`SO_RCVBUF` 8MB、`PACKET_QDISC_BYPASS` 跳过内核排队 | V0.15.0 |
| 内核真实丢包统计 | `PACKET_STATISTICS` 每 128 个包查询一次，`drop_packets` / `drop_rate` 反映内核丢包 | V0.15.0 |
| 取消与关闭语义 | `SO_RCVTIMEO` 200ms，`Next(ctx)` 响应取消，`Close()` 可重复调用且不长时间阻塞 | V0.17.0 |
| 采集过滤 `capture.filter` | pcap 常用子集（协议 / 主机 / 网段 / 端口 / and-or-not），不匹配的帧在**解析前**丢弃、**不计入丢包** | V0.18.0 |
| 内核级过滤剪枝 | `live` 下把过滤条件编译成**保守超集** BPF 程序，经 `SO_ATTACH_FILTER` 挂到每个套接字：只剪枝、不误丢；无法精确判断（VLAN / IPv6 扩展头 / `not` / 短帧）一律保守放行；挂载失败自动退回用户态 | V0.20.0 |

### 2.3 解析层

| 协议 | 覆盖情况 | 版本 |
| --- | --- | --- |
| 以太网 | 含**单层 VLAN 与 QinQ** 标签跳过 | V0.1 |
| IPv4 | 含 IHL 可变头（IP 选项），分片报文按首片语义解析 | V0.1 |
| IPv6 | 含**常见扩展头**（逐跳 / 路由 / 分片 / 目的选项，最多 4 个） | V0.13.0 |
| TCP | 端口、标志位（SYN/FIN/RST…）、数据偏移 | V0.1 / 状态机 V0.14.1 |
| UDP / ICMP / ICMPv6 | 端口（ICMP 无端口）、ICMPv6 协议号 58 | V0.1 / ICMPv6 V0.13.0 |

### 2.4 会话流表

- **5 元组双向归并**：A→B 与 B→A 合并为一条会话，保留首次观测方向；
- **双超时**：空闲 30 秒即落盘，最长 5 分钟强制结束；
- **TCP 状态机**：统计连接建立（SYN）与关闭（FIN/RST），输出 `new_conns` / `closed_conns`（V0.14.1）。

### 2.5 聚合与自身健康

- 秒级（`tick_ms` 可调）产出 6 个指标：`traffic.bps` / `pps` / `conns` / `newconns` / `closedconns` / `drops`；
- 丢包率 = 丢包 / (收包 + 丢包)，网页与客户端都会在丢包时给出明确提示（不只是数字）。

### 2.6 存储

| 后端 | 说明 | 版本 |
| --- | --- | --- |
| **SQLite（默认）** | WAL + `synchronous=NORMAL`、指标批量事务写入、会话索引 `idx_flows_proto_start` / `idx_flows_src_ip` / `idx_flows_dst_ip` | V0.2 / 优化 V0.14.2 |
| JSONL 文件 | `storage = "file"`，逐条追加、原子重写，便于人工查看 | V0.1 / 原子重写 V0.15.1 |
| 保留策略 | 按 `retention_hours` 自动清理过期指标与流记录 | V0.1 |

### 2.7 对外接口

- **REST 19 个接口**（全表见附件 A）：`/api/v1` 前缀 18 个 + Prometheus 文本格式的 `GET /metrics`（V0.22.0）；
- **SSE 实时通道** `GET /api/v1/stream`：每秒推送指标快照 + 告警事件，客户端支持自动重连与轮询降级（V0.10.0）；
- **可选 Bearer Token 鉴权**：`[api] token` 非空时，`/api/` 请求需带 `Authorization: Bearer <token>`（常量时间比较），`/api/v1/stream` 支持 `?token=`（V0.3）；
- **内嵌网页仪表盘**：`go:embed` 打包，带宽/包速率曲线支持折线 / 面积切换与放大、缩小、重置、滚轮缩放。

### 2.8 告警引擎

| 能力 | 说明 | 版本 |
| --- | --- | --- |
| 阈值 + 持续时长 | `bps` / `pps` / `conns` / `drops` 四类规则，需连续超阈值 N 秒才触发 | V0.5.1 |
| 事件历史 | `GET /api/v1/alerts?status=firing|resolved|all` | V0.5.1 |
| Webhook 通知 | 触发/恢复时 POST 到 `alert.webhook` | V0.5.1 |
| 告警联动抓包 | 触发时自动导出 pcap 作为证据留存（`alert.auto_capture`） | V0.12.0 |

### 2.9 白名单运维动作（21 个 / 5 类）

| 分类 | 动作 | 数量 |
| --- | --- | --- |
| 系统 | `system.os` `system.disk` `system.memory` `system.load` `system.top` `system.users` | 6 |
| 网络 | `net.addrs` `net.route` `net.listen` `net.stat` `net.ping` | 5 |
| 服务 | `service.status` `service.start` `service.restart` `service.stop` | 4 |
| 日志 | `log.journal` `log.service` `log.dmesg` | 3 |
| 文件 | `file.list` `file.du` `file.tail` | 3 |

统一约束：**执行前展示将要运行的完整命令**、参数校验、危险动作（start/stop/restart/ping 等）需二次确认、全部写入审计历史（`GET /api/v1/actions/history`）。（V0.8.0；V0.12.5 客户端整合为单一「Linux 指令」面板）

### 2.10 文件通道

白名单目录浏览与下载：`GET /api/v1/files`（列目录）、`GET /api/v1/files/download`（下载到 Windows），路径做白名单与穿越校验（V0.9.0）。

### 2.11 抓包导出与 Wireshark 联动

`POST /api/v1/capture/dump?seconds=15`（1~60 秒）导出 pcap，`GET /api/v1/capture/dump` 查状态、`/capture/dump/file` 下载；客户端一键下载到本机临时目录并用 Wireshark 打开（V0.7.0）。

### 2.12 安全版自升级

`POST /api/v1/system/upgrade`：默认关闭，开启后要求**白名单 URL 前缀 + SHA256 匹配 + ELF 校验 + 大小上限**，采用原子替换并保留备份，可回滚；客户端提供"一键升级服务端"入口（只发起与展示，安全约束全在服务端）。（V0.16.0 / 客户端 V0.12.4）

### 2.13 界面插件框架（服务端部分）

- 配置 `[plugins] dir` 指向插件目录，采集端读取其中的 `*.json` **声明式清单**（V0.19.0）；
- 清单可声明 `kpi` / `table` / `text` 三类面板块，接口地址必须以 `/api/v1/` 开头；**不含任何可执行代码**；
- 双重校验：id 命名规则、类型白名单、单文件 64KB、最多 32 个插件、每块最多 12 字段/列、重复 id 取首个；
- 坏文件只跳过并在 `GET /api/v1/plugins` 的 `warnings` 与日志里说明原因，不影响采集；
- 能力上报 `plugins`，客户端据此决定是否展示插件入口。

### 6.3 离线验证手段

1. **pcap 回放集成测试**：采集 → 解析 → 流表 → 聚合 → 存储整条链路不依赖真实网络；
2. **BPF 解释器**：`internal/filter/bpf_test.go` 自带与内核语义一致的解释器（越界 load 直接丢包），
   用它验证"内核程序是用户态条件的超集"这一不变式（30+ 表达式 × 11 类报文）；
3. **应用级冒烟**：synthetic / replay 启动采集端，检查日志与 `/api/v1/traffic/now` 字段。

## 7. 未实现 / 规划

### 7.1 阶段三（性能与扩展）剩余

| 项 | 状态 |

| 多队列 CPU 绑定（`[capture] cpu_pin`） | ✅ 已完成（V0.21.0） |
| `PACKET_MMAP` 环形缓冲（近零拷贝） | ❌ 未实现，**需在真实网卡上压测**（基线脚本：`deploy/bench-capture.sh`） |
| eBPF / XDP 加速 | ❌ 未启动 |
| NetFlow / sFlow 接入 | ❌ 未启动 |
| DPI（应用级识别） | ❌ 未启动 |

### 7.2 路线图剩余（详见[版本记录](版本记录.md)）

- **V3** 客户端增强：推送升级、多机对比、Windows 原生通知、帮助中心型 AI；
- **V4** 流量控制：Linux 端 `tc` 限速（仅本机流量，默认关闭 + 二次确认）+ 控制 API/界面；
- **V5** LLM 助手（RAG）、Agent + 中心聚合分布式、NetFlow/sFlow、DPI、eBPF；
- **界面插件框架**已随 V0.19.0 完成（阶段二 100%），不再挂起。

### 7.3 已知限制（如实记录）

1. **内核剪枝尚未在真实网卡上验证**：程序语义由离线 BPF 解释器验证，`SO_ATTACH_FILTER` 调用只做了 Linux 交叉编译与 `go vet`；
   需在 Linux 上确认日志 `[filter] 内核剪枝已启用` 与 `filter_kernel=true`；
2. 采集过滤的**端口条件**在 IPv6 侧与带 IP 选项的报文上保守放行（精确判定在用户态完成）；
3. 大流量下的性能结论（`PACKET_MMAP` 收益、多队列扩展性）需真机压测，当前不给数字；
4. 会话查询的 IP 过滤是子串匹配（`LIKE '%x%'`），无法走索引；
5. 客户端 Rust 侧未在无 Rust 工具链的环境重新构建（前端产物已验证）。

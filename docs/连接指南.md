# MeTD / netmon 连接指南（Windows ↔ Linux 虚拟机）

> 适用版本：采集端 **V0.21.0** / 客户端 **V0.12.8**（2026-09-24）
> 已在 **Windows 宿主机 + Ubuntu 虚拟机** 上完成一次完整验收（部署 → 抓包 → 客户端连接 → 仪表盘）。
> 配套文档：[使用指南](使用指南.md)（完整功能与配置）、[功能清单](功能清单.md)、[更新日志](更新日志.md)。

## 0. "连接"其实有 5 条路，先对号入座

| # | 谁 → 谁 | 用什么 | 典型用途 |
| --- | --- | --- | --- |
| 1 | 浏览器 → Linux 采集端 | HTTP `http://<IP>:8080` | 零安装看一眼；确认服务活着 |
| 2 | Windows 客户端 MeTD → Linux 采集端 | REST + SSE（经 Rust 命令层） | 日常使用（图表 / 会话 / 排行 / 指令 / 插件） |
| 3 | Windows → Ubuntu | SSH / SCP | 部署、更新、看日志、抓包排错 |
| 4 | 客户端「主机」面板 → 多台采集端 | 客户端并发探测各家 `/api/v1/traffic/now` | 一屏看多台机器并切换 |
| 5 | 客户端 → 采集端 | `POST /api/v1/system/upgrade` | 服务端一键升级（需服务端开启 `[update]`） |

下面按"先把 Linux 跑起来 → 再从 Windows 连过去"的顺序展开。

## 1. 准备工作（虚拟机网络与地址）

### 1.1 选对虚拟机网络模式

| 模式 | Windows 宿主机能否访问虚拟机 IP | 局域网其他机器 | 说明 |
| --- | --- | --- | --- |
| **桥接（Bridged）** | ✅ | ✅ | 推荐：虚拟机像一台独立机器，IP 与宿主机同网段 |
| NAT | ✅（常见：VMnet8 / 192.168.x.x 网段） | ❌ | 只在宿主机上用时够用；要给别人访问就改桥接或做端口转发 |
| 仅主机（Host-only） | ✅ | ❌ | 完全隔离的内网，适合练手 |

判断方法：在 Ubuntu 里 `ip -br a` 看地址，再在 Windows 里 `ping <那个地址>`。

### 1.2 拿到 Ubuntu 的 IP 与网卡名

```bash
ip -br a
# 输出示例：
# lo               UNKNOWN        127.0.0.1/8
# ens33            UP             192.168.161.128/24      ← 用这个 IP + 网卡名
```

**网卡名要填进配置里的 `capture.iface`**，Ubuntu 常见 `ens33` / `ens160` / `enp0s3`，云主机常见 `eth0`。

### 1.3 在 Windows 侧确认连通

```powershell
ping 192.168.161.128
Test-NetConnection 192.168.161.128 -Port 8080   # 采集端还没起时 False 是正常的
ssh wuki@192.168.161.128                        # 能登录才谈得上部署
```

## 2. Ubuntu 侧：把采集端跑起来（6 步）

### 2.1 准备二进制

仓库根目录的 `netmon-linux` 可能是**旧版本**（本次整合时它是 2026-09-19 构建的，不含采集过滤 / 插件 / 内核剪枝）。
先重新构建，二选一：

```powershell
# Windows 交叉编译（推荐，无需在虚拟机装 Go）
cd "D:\Codex\Linux network control"
$env:GOOS="linux"; $env:GOARCH="amd64"; $env:CGO_ENABLED="0"
go build -o netmon-linux ./cmd/netmon
Remove-Item Env:GOOS,Env:GOARCH,Env:CGO_ENABLED
```

```bash
# 或在 Ubuntu 上直接编译（需先 apt install -y golang-go 或用官方 tarball）
cd ~/Linux-network-control && go build -o netmon-linux ./cmd/netmon
```

### 2.2 上传

```powershell
# 方式 A：命令行
scp "D:\Codex\Linux network control\netmon-linux" wuki@192.168.161.128:/home/wuki/

# 方式 B：一键更新脚本（先 DryRun 看它要执行什么）
cd "D:\Codex\Linux network control"
.\deploy\upload-netmon.ps1 -Server 192.168.161.128 -User wuki -DryRun
.\deploy\upload-netmon.ps1 -Server 192.168.161.128 -User wuki
```

方式 B 会在远端自动完成"停旧进程 → 备份旧二进制 → 替换 → 启动 → 请求 `/api/v1/traffic/now` 校验版本"，失败可用
`ssh wuki@192.168.161.128 '~/update-netmon.sh --rollback'` 回滚。方式 C（FinalShell / WinSCP 拖文件）最简单，但要自己启动。

### 2.3 写配置 `config.toml`

```toml
[core]
machine_id = "ubuntu-vm"        # 客户端里显示的机器名
source     = "live"             # live 真实抓包 / replay 回放 / synthetic 造包
tick_ms    = 1000

[capture]
iface   = "ens33"               # ← 换成 1.2 里看到的真实网卡名
readers = 1                     # 流量大再调 2~8（多套接字 + PACKET_FANOUT）
cpu_pin = false                 # readers>1 时可开启：把各读循环绑到不同 CPU（V0.21.0）
# filter = "tcp and dst port 443"   # 可选：只看关心的流量（V0.18.0，live 下自动做内核剪枝）

[storage]
storage         = "sqlite"
sqlite_path     = "/home/wuki/netmon.db"
retention_hours = 24

[api]
listen = ":8080"                # 监听所有网卡；只在宿主机访问也可写 "127.0.0.1:8080"
token  = ""                     # 建议设一个（例如 "my-secret"）：设了客户端必须填同一个
```

常见可选段（本次整合后的版本都支持，按需加）：

```toml
[alert]                          # 告警：阈值 + 持续时长 + Webhook + 联动抓包
enabled = true
bps_threshold = 100000000        # 100 Mbps
bps_for_secs = 30
drops_threshold = 50
auto_capture = true              # 触发告警时自动导出 pcap

[plugins]                        # 界面插件：目录里放 *.json 声明式清单
dir = "/home/wuki/netmon-plugins"

[update]                         # 允许客户端"一键升级服务端"（默认关闭）
enabled = true
allowed_prefixes = "https://github.com/wukiQAQ/"
service = "netmon"
```

### 2.4 启动与权限

```bash
cd ~
chmod +x netmon-linux
sudo ./netmon-linux -config config.toml      # live 抓包需要 root 或 CAP_NET_RAW
# 不想用 sudo：
sudo setcap cap_net_raw=eip ./netmon-linux && ./netmon-linux -config config.toml
```

看到这几行就是正常：

```
[capture] 多队列 CPU 绑定已启用：reader0→CPU0 reader1→CPU1     # 仅在 cpu_pin=true 且 readers>1 时出现
[filter] 已启用采集过滤: tcp and dst port 443                    # 仅配置了 filter 时出现
[filter] 内核剪枝已启用（N 条 BPF 指令；程序为超集，精确匹配仍在用户态）   # 仅 live + filter 时出现
[api] HTTP 服务启动: http://localhost:8080
```

### 2.5 放行防火墙

```bash
# Ubuntu（ufw）
sudo ufw status
sudo ufw allow 8080/tcp

# CentOS / RHEL / Rocky（firewalld）
sudo firewall-cmd --permanent --add-port=8080/tcp && sudo firewall-cmd --reload
```

> 只在 Windows 宿主机访问、且 `listen` 写的是 `127.0.0.1:8080` 时不需要放行；但客户端里要填的地址也会随之变成
> `127.0.0.1:8080`（仅限本机，虚拟机内的 SSH 隧道场景才这么用，见第 6 节）。

### 2.6 自检（三层）

```bash
# ① 服务自己活着吗
curl http://127.0.0.1:8080/api/v1/traffic/now
# ② 用虚拟机对外 IP 再试一次（这一步才能证明"外部可访问"）
curl http://192.168.161.128:8080/api/v1/traffic/now
# ③ 看版本与能力（决定了客户端哪些面板可用）
curl -s http://127.0.0.1:8080/api/v1/traffic/now | grep -o '"version":"[^"]*"'
curl -s http://127.0.0.1:8080/api/v1/traffic/now | grep -o '"features":\[[^]]*\]'
```

② 不通就回到 2.5（防火墙）与 1.1（NAT/桥接）。返回的 JSON 里有 `bps`/`pps`/`conns` 说明采集链路已经通了；
如果 `recv_packets` 一直是 0，多半是 `capture.iface` 写错网卡（见第 5 节）。

### 2.7 可选：开机自启（systemd，Ubuntu）

```bash
sudo tee /etc/systemd/system/netmon.service > /dev/null <<'EOF'
[Unit]
Description=Linux Network Traffic Monitor (netmon)
After=network-online.target
Wants=network-online.target

[Service]
ExecStart=/home/wuki/netmon-linux -config /home/wuki/config.toml
WorkingDirectory=/home/wuki
Restart=on-failure
RestartSec=3
AmbientCapabilities=CAP_NET_RAW

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload
sudo systemctl enable --now netmon
systemctl status netmon --no-pager
```

如果之前用 `nohup` 手工跑过，记得先 `pkill -f netmon-linux` 再启用服务，避免两个进程抢网卡；
`deploy/update-netmon.sh --fix-systemd` 也能一键把配置/数据搬到系统目录并重写 unit。

## 3. Windows 侧：连上去看

### 3.1 方式一：浏览器（零安装）

打开 `http://192.168.161.128:8080`，应看到带宽/包速率曲线、会话明细与丢包状态。
能看到页面但数据全 0 → 见第 5 节"收包为 0"。

### 3.2 方式二：客户端 MeTD（日常使用）

1. 打开 `metd.exe` → 左侧 **账号管理**；
2. 填写：
   - **名称**：随便写（`ubuntu-vm`）；
   - **服务器地址**：`192.168.161.128:8080`（**必须带端口**）。
     客户端会自动补 `http://`，也接受 `http://192.168.161.128:8080`；只支持 http/https，别写 `https://` 除非你前面有反代；
   - **访问令牌**：服务端 `[api] token` 设了才填，没设留空；
3. 点 **连接**（连接过程可随时点"取消连接"）；
4. 连上后建议做 4 项自检：

| 检查点 | 期望看到 | 说明 |
| --- | --- | --- |
| 连接日志里的服务端版本 | `V0.21.0`（或你实际部署的版本） | 版本旧 → 能力面板会置灰，需替换 `netmon-linux` |
| 已启用能力 | 含 `capture.filter` / `plugins` 等 | 缺哪项，对应面板就不可用 |
| 仪表盘 KPI | 带宽/包速率每秒跳动 | 不动 → 抓包没流量或网卡选错 |
| 抓包导出 | 「抓包导出（15 秒 pcap）」能下载 | 下载后可用 Wireshark 直接打开 |

### 3.3 方式三：多机（同一个窗口看多台）

先在账号管理里保存多台（可以是多台 Ubuntu 虚拟机），再进 **主机** 面板：客户端会并发探测各台的在线状态、版本与能力，
点某行的「切换」即可切换当前连接。适用场景：同时盯生产机和测试机。

### 3.4 连接成功后顺手能做的事

- **Linux 指令**：21 个白名单动作（系统/网络/服务/日志/文件），每条都先显示完整命令，危险动作二次确认；
- **排行**：近 1 小时的 TOP IP / 协议分布 / TOP 端口；
- **插件**：服务端 `[plugins] dir` 里放了清单就会出现面板（见使用指南第 13 节）；
- **采集过滤状态**：连接日志面板会显示服务端过滤表达式、已过滤帧数与"内核剪枝已启用"。

## 4. 连接方式对照速查表

| 连接方式 | 目标 | 端口 | 鉴权 | 连不通时最先看什么 |
| --- | --- | --- | --- | --- |
| 浏览器 | `http://<IP>:8080` | 8080/tcp | 无（静态页免鉴权） | `sudo ss -ltnp \| grep 8080` |
| 客户端 | `<IP>:8080` | 8080/tcp | `[api] token`（可选） | 地址是否漏了 `:8080` |
| SSH / SCP | `<user>@<IP>` | 22/tcp | SSH 密码或密钥 | `ping`、虚拟机网络模式 |
| 多机探测 | 各台 `<IP>:8080` | 8080/tcp | 各自 token | 逐台用 `curl` 验证 |
| 一键升级 | `POST /api/v1/system/upgrade` | 8080/tcp | token + 服务端 `[update]` | 服务端 `enabled`/白名单 |

## 5. 常见问题排查

| 现象 | 原因与处理 |
| --- | --- |
| 客户端"连接失败：拒绝/超时" | 服务没起或被防火墙挡：`systemctl status netmon`、`sudo ss -ltnp \| grep :8080`、`sudo ufw allow 8080/tcp` |
| 地址填 `192.168.161.128` 连不上 | 少了端口，默认 80。客户端填 `<IP>:8080` |
| 浏览器能开、客户端连不上 | 多为端口/协议写错（客户端只支持 http/https），或令牌不匹配 |
| 返回 401 / 提示令牌无效 | 服务端设了 `[api] token`，客户端令牌必须完全一致（区分大小写） |
| 虚拟机内 `curl` 通、Windows 不通 | 虚拟机是 NAT/仅主机模式，或 Windows 防火墙挡了；改桥接或加端口转发 |
| 换到另一台电脑访问不通 | NAT 模式下虚拟机 IP 只在本宿主机网段有效，改用桥接 |
| 网页能开，但 KPI 一直是 0 | `capture.iface` 写错网卡名，或 `source` 还是 `synthetic`；`ip -br a` 核对后重启 |
| 收包有数、会话为空 | 空闲会话约 30 秒后才落库，等一会儿点「刷新」 |
| 客户端提示"服务端缺少：抓包导出/运维动作" | 服务器跑的是旧二进制，重新编译上传 `netmon-linux` 并重启 |
| `permission denied` 启动不了 | 用 `sudo`，或 `sudo setcap cap_net_raw=eip ./netmon-linux` |
| 8080 被占用 | 改 `[api] listen`（如 `:9000`），客户端地址同步改端口 |
| SSE 偶发断开 | 客户端会自动重连并降级为轮询；检查中间是否有代理切断长连接 |
| 抓不到本机 127.0.0.1 的流量 | `live` 抓的是指定网卡（如 `ens33`），回环流量需另选 `lo` 网卡 |
| 想让虚拟机不开防火墙端口也能用 | 用 SSH 隧道：`ssh -L 8080:127.0.0.1:8080 wuki@<IP>`，客户端连 `127.0.0.1:8080` |

## 6. 停用 / 回滚 / 卸载

```bash
sudo systemctl stop netmon && sudo systemctl disable netmon    # 停用 systemd 托管
pkill -f netmon-linux                                          # 停掉手工 nohup 的进程
~/update-netmon.sh --rollback                                  # 回滚到最近一次备份的旧版本
sudo rm /etc/systemd/system/netmon.service && sudo systemctl daemon-reload   # 彻底移除 unit
rm -f ~/netmon.db ~/netmon.db-wal ~/netmon.db-shm               # 需要时删除数据
```

## 7. 已验证记录与性能基线建议

**已验证（2026-09-24）**：Windows 宿主机 + Ubuntu 虚拟机，按本文第 2、3 节完成
"交叉编译 → 上传 → 配置 `live` 抓包 → 启动 → ufw 放行 → 浏览器/客户端连接" 全流程，采集与客户端显示正常。

**下一步建议（为 `PACKET_MMAP` 做准备）**：先在真实负载下取基线，否则无法判断零拷贝到底有没有收益：

```bash
sudo bash deploy/bench-capture.sh -i ens33 -p 8080 -s 30
```

它会输出：网卡 `rx_packets` / `rx_bytes` / `rx_dropped` 增量、netmon 上报的累计收包与丢包、平均 bps/pps、
进程平均 CPU% 与 RSS 峰值。**改动前后各跑一次同样参数**，对比 `rx_dropped` 与 CPU% 即可。

> 更激进的压测（需要另一台机器配合）：`iperf3 -c <目标> -t 60 -P 8` 制造大流量，或 `sudo tcpreplay -i ens33 --pps 200000 sample.pcap` 回放固定速率流量。

# 版本记录（Version Log）

## 版本号规则

- **小更新只加最后一位**（修订号）：bug 修复、单点小功能、文档 / 脚本 / 部署调整，例如 `0.14.0` → `0.14.1`；
- **次版本 +1**：一次交付一批成体系的功能（修订号归零），例如 `0.14.1` → `0.15.0`；
- **主版本 +1**：架构级或不兼容变更，例如 `0.15.2` → `1.0.0`；
- 采集端与客户端各自维护版本号，只改动哪端就升哪端；已推送的版本号不回改。

> 留存机制：每个版本同时以 **git tag** 和 **docs/ 下的版本文档** 双重留存，便于回溯与回滚。
> 查看标签：`git tag -n`；切到某版本：`git checkout v0.3.0`。

## v0.17.0（采集端）/ v0.12.4（客户端）—— 一键升级入口与多队列采集（2026-09-19）

### 采集端 0.17.0

- **多队列并行收包**：新增配置 `[capture] readers`（1~8，默认 1）。`readers > 1` 时开多个 AF_PACKET 套接字，
  并让它们加入同一个 `PACKET_FANOUT`（按流哈希）组，因此**同一条会话的报文仍由同一个队列处理，顺序不会乱**；
  任何一步失败（开套接字 / 设置 fanout）都自动回退单队列，不影响抓包可用性。
- **关闭与取消更可靠**：套接字设置 `SO_RCVTIMEO`（200ms），读循环会周期性醒来检查关闭标志；
  单队列 `Next(ctx)` 现在也响应 `ctx` 取消（此前会一直阻塞在读操作上）。多队列关闭时先唤醒读循环再关套接字，
  避免"fd 号被复用"读到别的连接的数据。
- 能力上报新增 `capture.multiqueue`；`netmon.example.toml` 补回完整示例配置（含 `capture.readers` 说明）。
- **本轮未做**：PACKET_MMAP 零拷贝环形缓冲需要在真实网卡上专项压测，仍列为后续任务，不引入未经验证的 syscall 路径。

### 客户端 0.12.4

- **服务端一键升级入口**：连接成功后，侧边栏"连接日志与状态"面板出现 **"一键升级服务端…"**；
  弹窗要求填写新版本下载地址与 SHA256（两者先在客户端本地校验），二次确认后调用
  `POST /api/v1/system/upgrade`，并展示服务端返回的结果（是否替换、SHA256、是否已安排重启）；
  弹窗同时显示服务端**最近一次升级记录**。服务端未启用时会给出可操作提示，而不是只报错。
- 升级相关纯逻辑抽到 `client/src/upgrade.js`（能力判断、表单校验、结果文案），新增 6 组单元测试；
  前端测试脚本改为运行全部用例（此前漏跑 `smooth` / `topn`）。

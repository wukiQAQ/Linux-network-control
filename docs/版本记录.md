# 版本记录（Version Log）

## 版本号规则

- **小更新只加最后一位**（修订号）：bug 修复、单点小功能、文档 / 脚本 / 部署调整，例如 `0.14.0` → `0.14.1`；
- **次版本 +1**：一次交付一批成体系的功能（修订号归零），例如 `0.14.1` → `0.15.0`；
- **主版本 +1**：架构级或不兼容变更，例如 `0.15.2` → `1.0.0`；
- **采集端与客户端各自维护版本号**，只改动哪端就升哪端；两个号段**互不相干**，
  客户端 `0.12.10` 不代表落后于采集端 `0.23.3`，也不要求把数字对齐；
- 已推送的版本号不回改数字；需要更清楚的名字时新增带组件前缀的别名标签，而不是重命名旧标签。

> 留存机制：每个版本同时以 **git tag** 和 **docs/ 下的版本文档** 双重留存，便于回溯与回滚。
> 查看标签：`git tag -n`；切到某版本：`git checkout server/v0.22.0`。

### 标签命名（2026-09-28 起）

本文件与《更新日志》里的 `vX.Y.Z` 是**历史遗留的单流标签**：早期两个产品共用一个号段，
无法从名字看出归属（`v0.12.0` 属于采集端，而 `v0.12.1`~`v0.12.8` 属于客户端）。

- **旧标签 `vX.Y.Z` 全部原样保留**，名称与指向的提交都不变（已克隆的仓库不受影响）；
- 每个旧标签都有一个**带组件前缀的别名标签**，与它指向同一个提交，可互换使用：
  - 采集端：`server/v0.1.0`、`server/v0.2.0`、`server/v0.12.0`、`server/v0.13.0` ~ `server/v0.22.0`（共 16 个）
  - 客户端：`client/v0.3.0`、`client/v0.3.1`、`client/v0.4.0` ~ `client/v0.12.8`（共 26 个）
- **今后新增标签一律带前缀**：采集端 `server/vX.Y.Z`，客户端 `client/vX.Y.Z`。
  按此规则新增的标签（如 `server/v0.23.0`、`server/v0.23.1`、`server/v0.23.2`、`server/v0.23.3`、`client/v0.12.9`、`client/v0.12.10`）不再有对应的旧标签。

## v0.23.0（采集端）—— 离线回放可用（本机 Windows 分析 pcap）（2026-09-28）

- **修复的三个缺陷**：
  1. **回放结束即退出进程**：`internal/app/app.go` 的 `Run` 在报文通道关闭后直接 `return nil`，`cmd/netmon/main.go` 随即 `Shutdown` + 退出 → 离线场景表现为「双击闪一下就没」、接口连不上。现在 `runOffline` 在收尾后阻塞 `<-ctx.Done()`，HTTP 服务继续可用。

  3. **收尾不落盘残留会话**：现在回放完成后 `flushRemaining()` 落 `Table.Snapshot()`，短 pcap 也不会只剩已关闭会话。

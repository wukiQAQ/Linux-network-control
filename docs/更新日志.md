## v0.22.0（采集端）—— /metrics 指标导出 + 数据层修正 · 2026-09-26

### 新增（采集端 0.22.0）

- **`GET /metrics`：Prometheus 文本格式指标**，可直接接入 Prometheus / Grafana 等已有监控体系。
  - 格式：`Content-Type: text/plain; version=0.0.4`；指标统一 `netmon_` 前缀，**所有样本都带 `machine` 标签**，
    多台机器可以在同一个 Prometheus 里区分与聚合。
  - 指标清单：`netmon_build_info`（版本 + 机器名）、`netmon_feature_enabled`（每项能力一行，1 = 支持）、
    `netmon_traffic_bps` / `netmon_traffic_pps`、`netmon_conns_active` / `netmon_conns_new` / `netmon_conns_closed`、
    `netmon_drop_rate`、`netmon_uptime_seconds`、`netmon_flows_active`、
    `netmon_recv_packets_total`（counter）、`netmon_drop_packets_total`（counter）。
  - 启用 `[capture] filter` 时额外输出 `netmon_filter_info{filter="..."}`、`netmon_filter_kernel`（1 = 内核剪枝已启用）、
    `netmon_filter_dropped_total`；未启用过滤时这三条不出现，避免误判成"正在过滤"。
  - **鉴权**：`/metrics` 与 `/api/` 走同一套 Bearer 令牌（配了 `[api] token` 就必须带令牌），
    Prometheus 侧用 `bearer_token_file` 即可抓取。

### 变更（采集端）

- **会话 IP 过滤语义变更（破坏性）**：`GET /api/v1/sessions?ip=` 由"子串匹配"改为
  **完整 IP = 精确匹配（源或目的）、其它 = 前缀匹配**；旧的 `10.0%5` 这类首尾通配写法不再支持，
  请改成 `10.0.` 前缀。查询条件同时改为索引友好的区间条件（`EXPLAIN QUERY PLAN` 断言走 `idx_flows_src_ip` / `idx_flows_dst_ip`）。
- **排行改为存储层聚合**：`GET /api/v1/topn` 的 TOP IP / 协议分布 / TOP 端口改由存储层聚合（SQLite 走 SQL `GROUP BY`），
  **去掉旧版"最多取前 2 万条会话样本"的上限**，大流量下排行不再被样本截断；响应里旧的 `sampled` / `matched` 字段已移除
  （客户端只用 `total_flows` / `total_bytes`，界面无需改动）。JSONL 文件后端给出与 SQLite 一致的聚合结果（有对拍测试）。
- 采集端 `0.21.0` → **0.22.0**；客户端不变（`0.12.8`），界面与交互无需改动。
- 设计文档升到 **v1.6**（接口全表补 `/metrics`、能力→代码映射补两行）；《功能清单与说明》同步统计数字。

### 验证

- `gofmt -l` 无输出；`go build ./...`、`go vet ./...`、`go test ./...` 全绿；
  `GOOS=linux GOARCH=amd64` 交叉编译 + `go vet` 通过。
- 新增测试：`renderMetrics` 纯函数（HELP/TYPE 成对、标签转义 `a"b\c`、过滤指标按需出现）、
  `/metrics` 响应头与正文、`/metrics` 鉴权（无令牌 401 / 带令牌 200）、启用过滤时三条过滤指标；
  排行接口字段与协议名映射（`6 → TCP`）、旧 `sampled` / `matched` 已移除；
  聚合 SQLite ↔ 文件后端对拍（含带 IP 过滤的聚合）、IP 过滤两后端一致性（`10.0.0.1` 不再命中 `10.0.0.10`）、
  IP 前缀区间上界进位（`10.0.` → `10.0/`、全 `0xff` 无上界）。
- 前端 `npm test` **124 个用例仍全绿**（本轮未改客户端代码）。

### 使用方式

```yaml
# prometheus.yml 片段（令牌文件内容是 [api] token）
scrape_configs:
  - job_name: netmon
    metrics_path: /metrics
    bearer_token_file: /etc/prometheus/netmon.token
    static_configs:
      - targets: ["192.168.161.128:8080"]
```

## v0.21.0（采集端）—— 多队列 CPU 绑定 + 连接方法固化 · 2026-09-24

### 新增（采集端 0.21.0）

- **多队列 CPU 绑定**：配置新增 `[capture] cpu_pin`（默认 false）。`readers > 1` 时，每个读循环固定在自己的 OS 线程上
  并绑定到不同 CPU，减少线程在核间迁移带来的抖动。
  CPU 分配按**进程实际允许的 CPU 列表**（`sched_getaffinity`，cgroup / `taskset` 下可能只是子集）进行，
  核不够时按顺序循环复用；读不到列表或 `sched_setaffinity` 失败**只打印一条日志并继续**，不影响抓包。
  单队列（`readers = 1`）不绑定 —— 读取发生在调用方 goroutine 上，绑它没有意义。
- 启动日志会写明绑定结果：`[capture] 多队列 CPU 绑定已启用：reader0→CPU0 reader1→CPU1 …`；
  能力上报新增 `capture.cpupin`（客户端的能力列表里可见）。

### 新增（文档与工具）

- 新增 **[连接指南](连接指南.md)**：把"怎么连"固化成一篇 —— 虚拟机网络模式（桥接 / NAT / 仅主机）怎么选、
  拿 IP 与网卡名、上传与配置、启动与权限、防火墙放行、三层自检、浏览器/客户端连接、多机、连接速查表、
  14 条排错、停用与回滚；并记录本次 **Windows + Ubuntu 虚拟机**的真机验收（2026-09-24）。
- 新增 `deploy/bench-capture.sh`：Linux 侧**只读**采集性能基线 —— 网卡 `rx_packets`/`rx_bytes`/`rx_dropped` 增量、
  netmon 上报的累计收包与丢包、平均 bps/pps、进程平均 CPU% 与 RSS 峰值，供 `PACKET_MMAP` 之类的优化做"改前 vs 改后"对比。

### 变更

- 设计文档升到 v1.5：阶段三进度 **约 70% → 约 80%**，剩余 `PACKET_MMAP` 环形缓冲、eBPF/XDP、NetFlow/sFlow、DPI。

### 验证

- `gofmt -l` 无输出；`go build ./...`、`go vet ./...`、`go test ./...` 全绿；Linux 目标交叉编译与 `go vet` 通过；
- 新增测试：CPU 分配纯函数（一核一个 / 核不够循环复用 / 只有一个核 / 无可用 CPU 时不绑定 / 忽略非法 CPU 号 / 零队列）、

## v0.20.0（采集端）/ v0.12.8（客户端）—— 内核级过滤剪枝（保守超集，只剪枝不误丢） · 2026-09-22

### 新增（采集端 0.20.0）

- **过滤下沉到内核**：`live` 模式下，`capture.filter` 会被编译成一段经典 BPF 程序，
  经 `SO_ATTACH_FILTER` 挂到每个 AF_PACKET 套接字上（多队列时每个队列各挂一份），
  明显不匹配的帧在**内核态**就被丢掉，省掉拷贝、系统调用与解析开销。
- **安全前提：内核程序是用户态条件的"超集"** —— 凡是用户态会命中的帧，内核一定放行（宁可多放行，绝不误丢）：
  - 能精确判断的做精确判断：`ip` / `ip6` / `arp`、`[src|dst] host`、`[src|dst] net`，
    以及 IPv4 上的协议号（`tcp` / `udp` / `icmp` / `icmp6`，协议字节固定在偏移 23）；
  - 无法在固定偏移上安全判断的一律保守放行：VLAN / QinQ 标签帧、IPv6 报文（扩展头会改变协议字节）、
    `not` 子表达式、以及帧长不足的报文；
  - 端口类条件（`port` / `portrange`）下沉为"只放行 TCP/UDP"，精确端口匹配仍由用户态完成。
- **双重保险**：用户态过滤**始终生效**，内核程序只是前置剪枝；挂载失败（权限不足、内核不支持）只打印一条日志
  并自动退回"纯用户态过滤"，采集与判定结果不受影响。
- `GET /api/v1/traffic/now` 新增 `filter_kernel`（是否启用内核剪枝）；未启用过滤时不出现这些字段。

### 新增（客户端 0.12.8）

- 「采集过滤」一行会额外标注 **内核剪枝已启用**，并说明"已过滤 N 帧"只统计到达用户态的部分，
  避免把"数字变小"误判成过滤失效。

### 变更

- 采集端 `0.19.0` → **0.20.0**（采集层系统级改动）；客户端 `0.12.7` → **0.12.8**。
- 设计文档升到 v1.4：阶段三「内核级过滤剪枝」标记完成，剩余 `PACKET_MMAP` 环形缓冲、eBPF/XDP、NetFlow/sFlow、DPI。

### 验证

  无剪枝价值 / 数据源不支持（回放、演示、非 Linux）→ 静默跳过；

## v0.18.0（采集端）/ v0.12.6（客户端）—— 采集过滤：只盯住你关心的流量 · 2026-09-20

### 新增（采集端 0.18.0）

- **`capture.filter` 落地**：这个配置项自 MVP 起一直以"预留"状态存在，本次真正启用。
  表达式是 **pcap 过滤器的常用子集**，支持 协议（`ip` / `ip6` / `arp` / `tcp` / `udp` / `icmp` / `icmp6`）、
  主机（`[src|dst] host <IP>`）、网段（`[src|dst] net <CIDR>`）、端口（`[src|dst] port <端口>`、`portrange <起-止>`），
  以及 `and` / `or` / `not` 与括号；**空表达式表示不过滤**。例如：

  ```toml
  [capture]
  filter = "tcp and dst port 443"                      # 只看 HTTPS 出向流量
  # filter = "net 192.168.0.0/16 and not port 22"      # 只看内网、排除 SSH
  ```

- **不匹配的帧在解析之前丢弃**：省掉协议解析、流表与存储开销；被过滤的帧**不计入丢包**
  （丢包仍然只反映真实的采集丢弃），而是单独计数，随 `GET /api/v1/traffic/now` 的 `filter_dropped` 上报。
- **语义与解析器一致**：VLAN 标签（单层 / QinQ）与 IPv6 扩展头（逐跳 / 路由 / 分片 / 目的选项）会被跳过，
  因此 `tcp`、`port 443` 对带扩展头的报文同样成立；**pcap 回放模式同样生效**，过滤规则可以离线验证。

## v0.15.0 —— 采集层优化：缓冲复用 / 降低排队延迟 / 真实丢包统计 · 2026-09-19

### 优化

- **读缓冲复用**：`live` 抓包原先每个包都分配 64KB 读缓冲（外加一次负载拷贝），现在用 `sync.Pool` 复用读缓冲，
  每包只剩一次必要拷贝，高流量下 GC 压力显著下降。
- **跳过内核排队（PACKET_QDISC_BYPASS）**：抓包套接字设置该选项后，报文不再经过内核 qdisc 排队，
  减少一层延迟与排队丢包（Linux 3.14+；失败不影响启动）。
- **内核接收缓冲**：`SO_RCVBUF` 从 4MB 提到 8MB，进一步降低突发流量丢包概率。
- **丢包统计更真实**：改为读取内核侧统计 `PACKET_STATISTICS`（每 128 个包查询一次，避免每包系统调用），
  `/api/v1/traffic/now` 的 `drop_packets`/`drop_rate` 从此反映**内核真实丢包**，而不是只在读取出错时计数。

## v0.5.1 —— 告警引擎（V2 能力线首个里程碑）· 2026-09-09

### 新增

- **告警引擎（Linux 端，Go）**
  - 新增 `internal/alert` 包：阈值 + 持续时长状态机，持续超过阈值 N 秒才触发，指标回落后自动产生恢复事件；

```toml
pps_threshold = 0
conns_threshold = 0
drops_threshold = 0
webhook = ""                # 可选：钉钉/企业微信机器人等
```

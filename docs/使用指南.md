# Linux 网络流量监控系统 / MeTD —— 使用指南（V0.7.0）

> 本指南面向第一次接触本项目的人：先跑起来（第 1 节），再学会用（第 2 节客户端、第 3 节网页仪表盘），
> 最后按需要配置告警与自启（第 4、5 节）。命令均标注了运行位置（Windows / Linux）。

## 0. 这套软件是什么

```
Linux 服务器（采集端 netmon，Go）
        │  抓包 → 解析 → 会话归并 → 秒级聚合 → SQLite
        │  HTTP REST /api/v1 + 内嵌网页仪表盘
        ▼
Windows 电脑（客户端 MeTD，Tauri + Vue）  ←── 输入 IP:端口 即可远程查看
```

- **采集端 `netmon`**：跑在被监控的 Linux 机器上，负责抓包与统计，自带一个网页仪表盘；
- **客户端 MeTD**：跑在 Windows 上，输入 Linux 的 IP 与端口即可看实时带宽、历史曲线、会话明细和告警。

两条使用路径：只想快速看看效果 → 第 1.1 节（Windows 演示，1 分钟）；要监控真实服务器 → 第 1.2 节。

## 1. 快速开始

### 1.1 方式一：Windows 演示（合成流量，无需 Linux、无需管理员权限）

```powershell
cd "D:\Codex\Linux network control"
go run ./cmd/netmon            # 若提示找不到 go：$env:Path = "D:\Go\bin;" + $env:Path
```

- 浏览器打开 `http://localhost:8080` 即可看到仪表盘；
- 不需要配置文件，程序会自动使用默认配置（合成流量 + SQLite，数据在 `data\netmon.db`）；
- 终端按 `Ctrl+C` 停止。

### 1.2 方式二：监控真实 Linux 服务器（推荐）

1. 按第 2 节把采集端部署到 Linux 并启动；
2. 在 Windows 上按第 3 节启动 MeTD 客户端，填写 `Linux的IP:8080` 连接；
3. 连接成功后就能看到实时的带宽、包速率、并发连接、丢包率与历史曲线。

## 2. Linux 采集端：部署与运行

### 2.1 编译 Linux 版（在 Windows 上交叉编译）

```powershell
cd "D:\Codex\Linux network control"
$env:GOOS="linux"; $env:GOARCH="amd64"; $env:CGO_ENABLED="0"
go build -o netmon-linux ./cmd/netmon
Remove-Item Env:GOOS,Env:GOARCH,Env:CGO_ENABLED
```

也可以直接在 Linux 上执行 `go build -o netmon-linux ./cmd/netmon`。

### 2.2 上传到 Linux

- 图形化工具（FinalShell / WinSCP）：把 `netmon-linux` 拖到用户家目录，例如 `/home/wuki/`；
- 或命令行：`scp "D:\Codex\Linux network control\netmon-linux" wuki@服务器IP:/home/wuki/`。

### 2.3 写配置文件 `config.toml`

复制仓库里的 `netmon.example.toml` 修改，真实抓包的最小配置如下：

```toml
[core]
machine_id = "centos-wuki"     # 机器名，会显示在客户端信息行
source = "live"                # 真实抓包（synthetic 合成 / replay 回放 / live 抓包）
tick_ms = 1000                 # 聚合周期，1 秒

[capture]
iface = "ens33"                # 网卡名，用 ip -br a 查看（常见：eth0 / ens33 / enp0s3）

[storage]
storage = "sqlite"
sqlite_path = "/home/wuki/netmon.db"
retention_hours = 24           # 数据保留 24 小时，超期自动清理

[api]
listen = ":8080"               # 监听所有网卡的 8080 端口
token = ""                     # 建议设置：设置后远程访问需带 Bearer 令牌
```

### 2.4 启动

```bash
cd ~
chmod +x netmon-linux
sudo ./netmon-linux -config config.toml        # live 抓包需要 root 或 CAP_NET_RAW
```

看到 `[api] HTTP 服务启动: http://localhost:8080` 就说明成功，保持终端运行。
不想用 `sudo` 可以授予能力：`sudo setcap cap_net_raw=eip ./netmon-linux`。

### 2.5 放行防火墙并自检

```bash
sudo firewall-cmd --permanent --add-port=8080/tcp && sudo firewall-cmd --reload   # CentOS/RHEL
# Ubuntu: sudo ufw allow 8080/tcp
curl http://127.0.0.1:8080/api/v1/traffic/now
```

能返回 JSON（包含 `bps`、`pps`、`conns` 等字段）即正常。之后在 Windows 浏览器访问 `http://Linux的IP:8080` 也应能看到网页仪表盘。

> WSL2 场景：Windows 直接用 `http://localhost:8080` 即可（WSL 会自动转发）。

### 2.6 开机自启（systemd，可选）

```bash
sudo tee /etc/systemd/system/netmon.service > /dev/null <<'EOF'
[Unit]
Description=Linux Network Traffic Monitor
After=network.target

[Service]
ExecStart=/home/wuki/netmon-linux -config /home/wuki/config.toml
WorkingDirectory=/home/wuki
Restart=on-failure
AmbientCapabilities=CAP_NET_RAW

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload
sudo systemctl enable --now netmon
systemctl status netmon
```

## 3. Windows 客户端 MeTD

### 3.1 获取程序

- **直接使用已构建的程序**：`client/src-tauri/target/release/metd.exe`（绿色版，双击即用）；
- **自行构建**（需要 Node.js ≥ 20 与 Rust 工具链）：

```powershell
cd "D:\Codex\Linux network control\client"
npm install
npm run build:app        # 等价于 npx tauri build --no-bundle，产物：client\src-tauri\target\release\metd.exe
npm run build:installer  # 需要 NSIS 安装包时使用（等价于 npx tauri build）
# 开发调试：npm run dev 之后另开终端执行 npx tauri dev
```

> **注意：一定要用 Tauri CLI 构建（`npm run build:app` / `npx tauri build`）。**
> 直接用 `cargo build --release` 编出来的 exe 是"开发模式"二进制：它不内嵌前端资源，而是去连接
> `http://localhost:1420` 的开发服务器，在没有开 `npm run dev` 的机器上双击后只会出现一个空白窗口（看起来像"打不开"）。
> 判断方法：正常的生产 exe 不会加载本地 1420 端口；若发现窗口空白，请用上面的命令重新构建。

### 3.2 连接服务器

1. 打开 MeTD，左侧点「👤 账号管理」；
2. 填写三样东西：连接名称（可留空，默认用地址）、服务器地址（如 `192.168.161.128:8080`，可省略 `http://`）、访问令牌（Linux 端没设 `token` 就留空）；
3. 点「连接」。界面会依次显示：正在连接 → 已连接，并把过程写进「📋 日志」页；
   连接过程中按钮会变成 **「取消连接」**，等待太久可以直接点它中断（不会弹出失败提示）；
4. 连接失败时顶部横幅会给出原因（超时、401 令牌无效、地址格式错误等），可直接照着改。

> 连接成功的那一瞬间，这个 IP 就会**自动记入账号管理列表**（见 3.5），下次直接点一下即可连接。

### 3.3 仪表盘：实时指标与历史曲线

连接后主界面自上而下是：

1. **信息行**：机器名、数据源、运行时长、活跃流数量、最后更新时间；
2. **四张 KPI 卡片**：实时带宽、包速率、并发连接、丢包率（丢包率大于 0 时卡片变黄并提示"指标可能失真"）；
3. **历史流量曲线**（最近 1 小时）：带宽与包速率双 Y 轴。

历史曲线的三种样式与缩放操作：

| 操作 | 位置 | 说明 |
| --- | --- | --- |
| 折线图 / 面积图 / 柱状图 | 曲线卡片左上角三个带图标的按钮 | 切换后自动记住选择，下次打开还是这个样式 |
| 放大 ＋ / 缩小 － | 曲线卡片右上角 | 以当前视图中心缩放时间轴，右下角显示当前比例（如"显示 36%"） |
| 重置 | 曲线卡片右上角 | 恢复到完整时间范围（全量） |
| 鼠标滚轮 | 光标停在曲线上滚动 | 直接缩放时间轴；按住拖动可左右平移 |
| 底部缩放条 | 曲线下方 | 拖动两端或中间滑块精细调整查看区间 |

> 刷新节奏：上方 KPI 每秒刷新，曲线每 2 秒重建一次并**每秒补一个实时点**，
> 因此曲线最右端始终与上方数字一致；分桶粒度为 10 秒。

> 想看某个尖峰的细节：把鼠标放在曲线上滚动滚轮放大，或用底部缩放条把区间拉窄，再点「重置」回到全量。

### 3.4 会话明细

- 支持**按 IP 子串过滤**（如 `10.0`）、**按协议筛选**（TCP / UDP / ICMP）、分页浏览；
- 输入过滤条件后自动查询（400 毫秒防抖），也可以点「刷新」手动刷新；
- 列表为空是正常的：会话需要空闲超时（约 30 秒）后才会落库。

### 3.5 账号管理：连过的 IP 自动记入

- **自动记录**：任何一次连接成功，客户端都会把这个「名称 + 地址 + 令牌」写进账号管理列表；
- **按地址去重**：同一个 IP:端口 只会保留一条记录，重复连接只更新时间，不会越攒越多；
- **最近连接时间**：每条记录下方显示"刚刚连接 / 5 分钟前连接 / 2 天前连接"；
- **一键切换**：点列表项即可切换到该服务器，切换后自动重连并刷新指标、曲线与会话；
- **编辑 / 删除**：点「编辑」把记录载入表单（改完点「保存」覆盖），点「×」删除；
- **手动保存**：也可以填好地址后直接点「保存」，不必先连接。

> 记录保存在本机（localStorage），不会上传到任何服务器；令牌以明文保存在本机，请在个人电脑上使用。

### 3.6 多工作区（同一窗口看多台机器）

- 顶部标签栏点「＋」新建一个工作区，各自独立保存连接与数据；
- 标签上的**绿点**表示该工作区处于连接状态；点击标签即切回该页面，数据自动还原并重连；
- 点标签上的「×」关闭（至少保留一个）；所有工作区会持久化，重启程序后自动恢复。

### 3.7 设置中心、托盘与单实例

点左侧底部的「⚙️ 设置」：

| 设置项 | 说明 |
| --- | --- |
| 夜间模式 / 明亮模式 | 界面与图表配色整体切换，选择本地记忆（启动即生效，不闪白） |
| 面板背景透明度 | 55% ~ 100%，配合自定义背景图使用 |
| 自定义背景图片 | 选图后自动压缩（最大宽度 1920）并记忆，可一键恢复默认 |
| 开机自启动 | 打开后随 Windows 登录自动运行 |
| 启动时最小化到托盘 | 开机自启场景下不弹窗，直接进托盘 |
| 关闭窗口时最小化到托盘 | 点窗口关闭按钮不退出程序，而是收进托盘 |

- **系统托盘**：左键单击显示 / 隐藏窗口，右键菜单「显示 MeTD / 退出」；
- **单实例运行**：程序已在运行时，再次双击桌面快捷方式不会新开进程或托盘图标，而是唤起并前置已有窗口。

## 4. 抓包导出并用 Wireshark 分析（V0.7.0）

MeTD 可以把 Linux 端正在抓的流量导出成 pcap 文件，下载到本机后用 Wireshark 打开：

1. 连接成功后，主界面顶部会出现两个按钮：**「抓包导出（15 秒 pcap）」** 和 **「用 Wireshark 打开」**；
2. 点「抓包导出」后，Linux 端开始把经过的原始报文写入 pcap（默认 15 秒，后端允许 1~60 秒）；
   抓包期间按钮显示进度（已捕获包数 / 字节数 / 剩余时间）；
3. 抓包结束后客户端自动把文件下载到本机临时目录 `%TEMP%\MeTD-captures\`（文件名形如 `metd-capture-<时间戳>.pcap`）；
4. 随后自动调用 Wireshark 打开该文件；如果没自动打开，点「用 Wireshark 打开」即可，
   界面下方会显示最近一次的文件路径；
5. Wireshark 查找顺序：注册表登记的安装路径（支持装在 D 盘等非默认位置）→ PATH → 常见安装目录 → 系统默认程序。

对应的接口（也可以用 curl 直接调用，便于接入自己的脚本）：

```text
POST /api/v1/capture/dump?seconds=15    # 开始导出（同一时刻只允许一次）
GET  /api/v1/capture/dump               # 查询状态：active / ready / packets / bytes
GET  /api/v1/capture/dump/file          # 下载最近一次导出的 pcap
```

> 说明：抓包文件保存在 Linux 端配置的 `storage.data_dir`（默认 `data`）下的 `dumps` 子目录；
> 导出的 pcap 为标准小端、微秒时间戳、以太网链路格式，Wireshark / tcpdump / tshark 都能直接打开。

## 5. 告警（阈值 + 持续时长）

在 Linux 端配置文件的 `[alert]` 段开启（默认关闭，不改动不影响现有功能）：

```toml
[alert]
enabled = true
bps_threshold = 100000000   # 带宽阈值（bit/s），100 Mb/s；0 表示该规则不启用
bps_for_secs = 30           # 持续超过阈值 30 秒才触发
pps_threshold = 0           # 包速率阈值（包/s）
pps_for_secs = 30
conns_threshold = 0         # 并发连接数阈值
conns_for_secs = 30
drops_threshold = 0         # 每秒丢包数阈值
drops_for_secs = 30
webhook = ""                # 可选：触发时 POST JSON 事件到这个地址（企业微信/钉钉机器人等）
```

规则含义：指标**连续超过阈值 N 秒**才触发（防止毛刺误报），回落后自动记录一条恢复事件。

- 查看触发中的告警：`curl "http://Linux的IP:8080/api/v1/alerts?status=firing"`；
- 查看全部事件：`status=all`；已恢复：`status=resolved`；
- MeTD 客户端连接后每 5 秒查询一次，若存在触发中的告警，主界面顶部显示红色横幅（规则、指标、当前值与阈值）；
- 配置了 `api.token` 时，上述 curl 需要加 `-H "Authorization: Bearer 你的令牌"`。

## 6. 网页仪表盘（不装客户端也能看）

浏览器打开 `http://Linux的IP:8080`：

- KPI 卡片、带宽/包速率单位切换、系统健康、会话明细（IP / 协议 / 端口过滤 + 分页）；
- **流量趋势图**支持**折线 / 面积 / 柱状**三种样式切换，以及**放大 ＋ / 缩小 － / 重置**和**鼠标滚轮缩放**；
- 时间范围可选「近 10 分钟 / 近 1 小时」。

## 7. 配置文件字段说明

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `core.machine_id` | host-1 | 机器标识，显示在客户端与网页上 |
| `core.source` | synthetic | 数据源：`synthetic` 合成 / `replay` 回放 / `live` 抓包 |
| `core.tick_ms` | 1000 | 指标聚合周期（毫秒） |
| `capture.iface` | eth0 | `live` 模式监控的网卡 |
| `capture.filter` | 空 | BPF 过滤表达式（已预留，当前版本未实现） |
| `capture.replay_file` | 空 | `replay` 模式的 pcap 文件路径 |
| `capture.pps` | 200 | `synthetic` 模式的包速率 |
| `storage.storage` | sqlite | 存储后端：`sqlite` / `file`（JSONL） |
| `storage.sqlite_path` | data/netmon.db | SQLite 数据库文件 |
| `storage.data_dir` | data | `file` 后端的数据目录 |
| `storage.retention_hours` | 24 | 数据保留时长（小时） |
| `api.listen` | :8080 | HTTP 监听地址 |
| `api.token` | 空 | 可选 Bearer 令牌；设置后 `/api/` 请求需带 `Authorization: Bearer <token>` |
| `alert.*` | 关闭 | 告警规则，见第 4 节 |

## 8. REST API 一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/traffic/now` | 实时指标：bps、pps、conns、new_conns、recv_packets、drop_packets、drop_rate、uptime_s、flows_active |
| GET | `/api/v1/traffic/history?since=3600&step=60` | 历史曲线：from、to、step_s、points[] |
| GET | `/api/v1/sessions?ip=10.0&proto=tcp&page=1&page_size=10` | 会话明细与分页 |
| GET | `/api/v1/health` | 系统健康（与 traffic/now 同源） |
| GET | `/api/v1/alerts?status=firing` | 告警事件：firing / resolved / all |
| POST | `/api/v1/capture/dump?seconds=15` | 开始抓包导出（1~60 秒），可下载为 pcap |
| GET | `/api/v1/capture/dump` | 抓包导出状态（active / ready / packets / bytes） |
| GET | `/api/v1/capture/dump/file` | 下载最近一次导出的 pcap（Wireshark 可直接打开） |
| GET | `/` | 内嵌网页仪表盘 |

## 9. 数据、备份与清理

- 数据文件：`storage.sqlite_path`（默认 `data/netmon.db`，Linux 示例中为 `/home/wuki/netmon.db`）；
- 备份：复制该文件即可；WAL 模式下建议先停止服务，或使用 SQLite 在线备份命令；
- 清理：超过 `retention_hours` 的指标与会话由程序自动删除，无需手工维护。

## 10. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 会话列表为空 | 空闲会话需约 30 秒后才落库，等一会儿再点「刷新」 |
| `live 抓包仅支持 Linux` | Windows 只能跑 `synthetic` / `replay`，真实抓包请在 Linux 或 WSL |
| Linux 启动报 `permission denied` | 用 `sudo` 运行，或 `sudo setcap cap_net_raw=eip ./netmon-linux` |
| 8080 端口被占用 | 修改 `api.listen`（如 `:9000`），客户端地址同步改端口 |
| Windows 打不开网页仪表盘 | 检查 Linux 防火墙是否放行 8080、`listen` 是否为 `:8080`（不是 `127.0.0.1:8080`） |
| 客户端提示 401 / 令牌无效 | Linux 端 `api.token` 与客户端填写的令牌不一致，或改完没重启采集端 |
| 客户端一直连不上 | 确认 `curl http://Linux的IP:8080/api/v1/traffic/now` 在 Windows 上可用；NAT 虚拟机需做端口转发或改桥接 |
| 页面提示丢包 | 非 IPv4 帧（如 ARP）会被跳过并计入丢包统计，属正常现象 |
| 曲线只能看到最近的区间 | 说明时间轴被缩放了，点曲线卡片右上角「重置」回到全量 |
| 只能看到本机流量 | 程序只能看到流经所配置网卡的报文，镜像/交换机分流场景需自行配置 |
| 点「抓包导出」提示失败 | Linux 端版本需为 V0.7.0 及以上（旧版没有 `/api/v1/capture/dump` 接口） |
| 没自动打开 Wireshark | 抓包文件已保存在 `%TEMP%\MeTD-captures\`，可点「用 Wireshark 打开」或手动打开 |
| 连接一直转圈 | 点「取消连接」即可中断，然后检查 Linux 端是否启动、防火墙是否放行、令牌是否正确 |

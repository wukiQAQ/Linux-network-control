# Linux 网络流量监控系统 —— 使用指南（V0.3）

> 适用版本：V0.4（Windows 客户端更名 MeTD）  
> 适用环境：Windows（开发/演示）、Linux（真实抓包，含 CentOS 虚拟机、WSL Ubuntu）
> 配套阅读：[V0.2 运行原理与 SQLite 接入](V0.2-运行原理与SQLite接入.md)

## 1. 前置条件

- Go 工具链（本机为 `D:\Go`，终端若找不到 `go` 先执行：`$env:Path = "D:\Go\bin;" + $env:Path`）；
- 项目目录：`D:\Codex\Linux network control`；
- 国内网络建议先执行一次（永久生效）：

```powershell
go env -w GOPROXY="https://goproxy.cn,direct"
```

## 2. 三种运行模式

### 2.1 模式 A：Windows 演示（synthetic 合成流量，无需 root）

```powershell
cd "D:\Codex\Linux network control"
go run ./cmd/netmon
```

- 浏览器打开 `http://localhost:8080`；
- 不需要配置文件，未找到 `config.toml` 时自动使用默认配置（synthetic + SQLite）；
- 数据保存在运行目录 `data\netmon.db`；
- 停止：终端按 `Ctrl+C`。

### 2.2 模式 B：pcap 文件回放（离线测试）

1. 准备 pcap 文件（Wireshark 抓包或样例文件），如 `D:\sample.pcap`；
2. 创建 `config.toml`（复制 `netmon.example.toml` 修改即可）：

```toml
[core]
machine_id = "host-1"
source = "replay"
tick_ms = 1000

[capture]
replay_file = "D:\sample.pcap"

[storage]
storage = "sqlite"
sqlite_path = "data/netmon.db"
retention_hours = 24

[api]
listen = ":8080"
```

3. 运行：`go run ./cmd/netmon -config config.toml`；
4. 回放结束后程序自动退出（适合脚本与自动化测试）。

### 2.3 模式 C：Linux 真实抓包（CentOS 虚拟机 / 服务器 / WSL）

**第 1 步：Windows 交叉编译 Linux 版**

```powershell
cd "D:\Codex\Linux network control"
$env:GOOS="linux"; $env:GOARCH="amd64"; $env:CGO_ENABLED="0"
go build -o netmon-linux ./cmd/netmon
Remove-Item Env:GOOS,Env:GOARCH,Env:CGO_ENABLED
```

**第 2 步：上传到 Linux**

- FinalShell：打开左侧文件面板，把 `netmon-linux` 拖入用户家目录（如 `/home/wuki`）；
- 或 scp：`scp "D:\Codex\Linux network control\netmon-linux" wuki@服务器IP:/home/wuki/`。

**第 3 步：创建配置文件 `/home/wuki/config.toml`**

```toml
[core]
machine_id = "centos-wuki"
source = "live"
tick_ms = 1000

[capture]
iface = "ens33"            # 用 ip -br a 查看实际网卡名

[storage]
storage = "sqlite"
sqlite_path = "/home/wuki/netmon.db"
retention_hours = 24

[api]
listen = ":8080"           # 监听所有网卡
```

**第 4 步：运行（抓包需要 root）**

```bash
cd ~
chmod +x netmon-linux
sudo ./netmon-linux -config config.toml
```

看到 `HTTP 服务启动: http://localhost:8080` 即成功，保持终端开启。

**第 5 步：放行防火墙并验证**

```bash
# 另开一个终端
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload
sudo firewall-cmd --list-ports        # 应显示 8080/tcp
curl http://127.0.0.1:8080/api/v1/traffic/now
```

**第 6 步：Windows 浏览器访问**

```
http://CentOS的IP:8080
```

> WSL 场景下 Windows 直接访问 `http://localhost:8080`（WSL2 自动转发）。

## 3. 开机自启（systemd，可选）

```bash
sudo tee /etc/systemd/system/netmon.service > /dev/null <<'EOF'
[Unit]
Description=Linux Network Traffic Monitor
After=network.target

[Service]
ExecStart=/home/wuki/netmon-linux -config /home/wuki/config.toml
WorkingDirectory=/home/wuki
Restart=on-failure
AmbientCapabilities=CAP_NET_RAW

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload
sudo systemctl enable --now netmon
systemctl status netmon
```

## 4. 配置文件字段说明

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `core.machine_id` | host-1 | 机器标识（多机对比预留） |
| `core.source` | synthetic | 数据源：`synthetic` / `replay` / `live` |
| `core.tick_ms` | 1000 | 指标聚合周期（毫秒） |
| `capture.iface` | eth0 | `live` 模式监控网卡 |
| `capture.filter` | 空 | BPF 过滤表达式（预留） |
| `capture.replay_file` | 空 | `replay` 模式的 pcap 路径 |
| `capture.pps` | 200 | `synthetic` 模式包速率 |
| `storage.storage` | sqlite | 后端：`sqlite` / `file` |
| `storage.sqlite_path` | data/netmon.db | SQLite 数据库文件 |
| `storage.data_dir` | data | `file` 后端的目录 |
| `storage.retention_hours` | 24 | 数据保留时长（小时） |
| `api.listen` | :8080 | HTTP 监听地址 |
| `api.token` | 空 | 可选 Bearer 令牌；设置后 `/api/` 请求需带 `Authorization: Bearer <token>` | 

## 5. 页面与 API

页面：`http://IP:8080`（带宽曲线、KPI 卡片、会话明细、系统健康、单位切换）

API（浏览器直接访问或 curl）：

```text
GET /api/v1/traffic/now       当前实时指标
GET /api/v1/traffic/history?since=3600&step=60   历史曲线
GET /api/v1/sessions?ip=10.0&proto=tcp&page=1    会话列表
GET /api/v1/health            系统健康
```

## 6. Windows 桌面客户端 MeTD 连接（V0.4）

### 6.1 构建客户端（本机首次）

前置条件：Node.js ≥ 20、Rust 工具链（含 MSVC）。国内网络建议：

```powershell
# 客户端 npm 使用 npmmirror（client/.npmrc 已配置）
# Rust 工具链使用 rsproxy 镜像（CARGO_HOME/config.toml 已配置）
```

```powershell
cd "D:\Codex\Linux network control\client"
npm install
npx tauri build
```

产物：`client/src-tauri/target/release/metd.exe`（绿色版，双击即用，程序名 MeTD）。若需 NSIS 安装包，需在无 C/D 跨盘限制的环境执行完整 `npx tauri build`。

### 6.2 连接步骤

1. Linux 端先按第 2.3 节启动 netmon（live 抓包），并放行防火墙 8080 端口；
2. （可选）在 Linux 配置中加入令牌：`[api]` 段设置 `token = "你的令牌"`，重启 netmon；
3. Windows 打开 MeTD 客户端，填写连接名称、服务器地址（如 `192.168.1.100:8080`）与令牌；
4. 点"保存"可留存该连接，点"连接"进入仪表盘（实时 KPI / 历史曲线 / 会话明细 / 健康）；
5. 历史曲线可切换折线/面积/柱状三种样式（按钮带图标）；左侧"设置"区可切换夜间/明亮主题，选择会被本地记住；
6. **多开**：点击顶部标签栏的「＋」可在同一程序内新建工作区页面，各自独立连接与数据；点标签可切回原页面，数据自动还原并重连；

> 说明：令牌保存在客户端本地的 localStorage 与进程状态中，仅用于个人使用场景；连接中断时客户端会提示并停止轮询。

## 6.5 告警配置（V0.5.1）

在 Linux 端配置文件追加 `[alert]` 段并重启 netmon：

```toml
[alert]
enabled = true
bps_threshold = 100000000   # 100 Mb/s
bps_for_secs = 30
pps_threshold = 0           # 0 = 不启用该规则
conns_threshold = 0
drops_threshold = 0
webhook = ""                # 可选：通知地址，收到 POST JSON 事件
```

- 规则含义：指标"持续超过阈值 N 秒"才触发，回落后自动记录恢复事件；
- 查看事件：`curl http://Linux的IP:8080/api/v1/alerts?status=firing`（若配置了 `api.token`，需带 `Authorization: Bearer <token>`）；
- MeTD 客户端连接后，若有触发中的告警，主界面顶部会出现红色横幅。
## 7. 使用要点与常见问题

| 现象 | 说明/解决 |
| --- | --- |
| 会话列表为空 | 会话在空闲超时（30s）后才落库，等 30~60 秒再查询 |
| 页面有丢包提示 | MVP 把非 IPv4 帧（ARP 等）计为跳过，属正常；不影响功能 |
| `live 抓包仅支持 Linux` | Windows 用 synthetic/replay；真实抓包在 Linux/WSL |
| `permission denied`（Linux） | 用 `sudo` 或 `sudo setcap cap_net_raw=eip ./netmon-linux` |
| 8080 被占用 | 修改 `api.listen` 如 `:9000` |
| Windows 访问不到 VM | 放行防火墙；NAT 网络用 FinalShell 端口转发或改桥接 |
| 只统计本机流量 | 程序只能看到流经该网卡、且本机收发/转发的包 |
| 客户端报 401 / 令牌无效 | Linux 端 `[api] token` 与客户端填写的令牌不一致；或 Linux 端未重启 |
| 客户端连不上 | 检查 Linux 防火墙 8080、监听地址 `:8080`、Windows 与 Linux 网络互通（同网段/桥接） |
| 会话列表为空 | 空闲会话需约 30 秒后才落库，等待后点"刷新" |

## 7. 数据与备份

- SQLite 数据库：配置的 `sqlite_path`（默认 `data/netmon.db`）；
- 备份：直接复制该文件即可（WAL 模式下建议先停止服务或使用 sqlite 在线备份）；
- 保留策略：超过 `retention_hours` 的数据在运行中自动清理。
